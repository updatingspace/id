# Карта проверок

Тесты разделены по проверяемой границе. Скрипт с именем `smoke-web-*.sh` не всегда является самим браузерным тестом: в действующих сценариях он часто поднимает одноразовую YDB, API, web и mock-сервер, затем запускает Chromium через `@playwright/test`. Сценарий в браузере находится в `services/id-rust/scripts/*browser.cjs`. Названия появились в ходе миграции и пока смешивают запуск окружения с проверками; это технический долг, а не отдельный веб-протокол.

| Уровень | Чем проверяется | Что доказывает |
| --- | --- | --- |
| Шаблон и обработчик | Rust unit/integration tests | Разметка, ветвление флагов, API-контракт |
| Реальная локальная база | Rust `--ignored` YDB tests | Транзакции и состояние одноразовых данных |
| Браузер | Playwright/Chromium из `browser-tests` | Действия пользователя и состояние страницы |
| Оболочка теста | Bash в `scripts` | Запуск/остановка процессов, порты, локальная YDB |

Для нового поведения страницы сначала добавляйте проверку в Rust или Playwright. Новую проверку DOM через `curl | rg` не стоит оформлять как самостоятельный веб-тест. Если браузерному сценарию требуется локальная YDB, оставляйте оболочку только для настройки окружения и очистки. В CI различайте браузерный результат, готовность локального fixture и проверку реально развёрнутого сервиса.

Проверка `scripts/wait-for-ydb-local.sh` вызывается основным и расширенным workflow: она создаёт и удаляет временную таблицу после запуска локального контейнера. Это инфраструктурная готовность теста, а не тест интерфейса и не код production. Для полномасштабной замены существующих shell-оболочек нужны отдельные fixture и управление процессами в тестовом раннере; простая смена расширения на JavaScript качества не добавит.
