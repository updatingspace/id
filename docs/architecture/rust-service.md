# Устройство Rust-сервиса

UpdSpace ID состоит из нескольких процессов. Их исходники живут в [`services/id-rust`](../../services/id-rust/README.md); маршруты и флаги включения проверяйте в текущей версии кода и окружения, а не по старым результатам пилотов.

| Компонент | Ответственность | Где искать |
| --- | --- | --- |
| `id-api` | Вход, сессии, профиль, MFA, OAuth/OIDC и запросы на данные | `crates/id-runtime/src`, бинарник `id-api` |
| `id-web` | Публичные и личные страницы; получает данные через API | `crates/id-web` |
| `id-jobs` | Письма и отложенные операции | `crates/id-runtime/src/bin/id-jobs.rs` |
| `idctl` | Операторские проверки и адресные операции | `crates/id-runtime/src/bin/idctl` |
| `id-compat` | Совместимость существующих паролей, сессий и MFA | `crates/id-compat` |

## Границы данных

YDB хранит аккаунты, сессии, доступы и служебные операции. `id-web` не обращается к YDB напрямую и не хранит ключи подписи: страница использует ответы `id-api`. Изображения и архивы данных находятся в отдельном объектном хранилище. Приватные операции фоновых заданий не должны маршрутизироваться наружу. Рабочая схема окружения и порядок выпуска описаны в [эксплуатации](../operations.md).

Rust сохраняет форматы действующих credentials и связи аккаунта при переходе со старого runtime. Изменение этих форматов требует отдельной проверки совместимости на существующих данных. Схема базы и включение маршрута — разные шаги: наличие кода само по себе не означает, что функция готова к работе.

## Удаление аккаунта

В коде есть подтверждаемое удаление и фоновая очистка. На 21 октября 2026 года в рабочем окружении флаги API, jobs и web выключены, поэтому кабинет не показывает кнопку удаления. Обращение по почте не подтверждает владение аккаунтом и не заменяет это действие. Перед включением нужны проверка восстановления фоновой операции, конечного состояния в YDB и хранилище, сценария уже запрошенного экспорта, а также репетиция на одноразовом аккаунте. Страница [эксплуатации](../operations.md) фиксирует границу выпуска; план работ — в [плане развития](../development/id-development-plan-2026-10-13.md).

## Сертификат Yandex Cloud

Файл [`YandexInternalRootCA-2.crt`](../../services/id-rust/certs/YandexInternalRootCA-2.crt) — публичный корневой сертификат удостоверяющего центра, **не** приватный ключ и не сертификат нашего сайта. Dockerfile добавляет его в системное хранилище доверия образов. Клиент YDB может отдельно загрузить CA через `YDB_CA_FILE` и сохраняет проверку DNS-имени сервера; отключения TLS-проверки в этом пути нет. Хранение сертификата рядом с рецептом образа закрепляет входные данные сборки. Перед его заменой нужно сверить отпечаток с официальной цепочкой и проверить соединение с YDB. [Yandex Cloud описывает добавление своего CA в контейнер](https://yandex.cloud/en/docs/serverless-containers/concepts/runtime).
