# Письма аккаунта и восстановление доступа

Вход содержит ссылки «Забыли пароль?» и «Подтвердить email». Пользователь может
запросить восстановление и повторное подтверждение без активной сессии. После
регистрации письмо ведёт на `/verify-email`; после запроса сброса — на
`/reset-password`. Открытие страницы не расходует ссылку: действие выполняется
только по кнопке. Ключ хранится во фрагменте URL (`#key=…`), который браузер не
передаёт серверу в URL запроса или Referer.

Ссылка сброса действует один час (`PASSWORD_RESET_TIMEOUT`, секунды), проверяется
Django/allauth и перестаёт работать после смены пароля. Сброс не отключает MFA,
не создаёт авторизованную сессию и отзывает существующие сессии, JWT refresh,
OIDC-токены и незавершённые OIDC-коды/запросы. Для ещё не подтверждённого аккаунта
нужно отдельно подтвердить email. Восстановление отправляется только на адрес входа,
а не на дополнительные адреса, ожидающие подтверждения. Вход с паролем соблюдает обязательное подтверждение.

Письма UpdSpace ID содержат текстовую и HTML-версии: подтверждение email, ссылка
сброса, подтверждение смены/сброса пароля, смена email, включение/выключение TOTP,
обновление резервных кодов, добавление/удаление Passkey. Уведомления о новом
устройстве также отправляются. Пароли, TOTP-секреты и резервные коды по email
не передаются.

## iCloud и account@updspace.com

Шаблон переменных: [`email.icloud.env.example`](../email.icloud.env.example).
Django читает окружение процесса; `.env` автоматически не загружается.

1. В iCloud Custom Email Domain создайте и активируйте `account@updspace.com`.
   Домен `updspace.com` и его DNS-записи должны быть подтверждены в iCloud.
2. Создайте отдельный пароль приложения Apple для сервиса ID в разделе
   «Вход и безопасность → Пароли приложений» на [account.apple.com](https://account.apple.com/).
3. Настройте `EMAIL_HOST=smtp.mail.me.com`, порт `587`, `EMAIL_USE_TLS=true`,
   `EMAIL_USE_SSL=false`. В `EMAIL_HOST_USER` укажите полный основной адрес
   iCloud Mail, принадлежащий владельцу этого адреса домена. Отправитель
   `DEFAULT_FROM_EMAIL='UpdSpace ID <account@updspace.com>'` задаётся отдельно.
4. Сохраните пароль приложения в Lockbox как `EMAIL_HOST_PASSWORD` и передайте
   его серверному контейнеру через существующий механизм секретов. Не храните
   пароль в Git, открытых tfvars или истории shell. Поддерживается также
   `EMAIL_HOST_PASSWORD=@/путь/к/файлу-секрета`.
5. Укажите `ID_FRONTEND_BASE_URL` с публичным адресом интерфейса без `/api/v1`.
   По умолчанию используется существующий `ID_ACTIVATION_BASE_URL`.
   Для локальной разработки это `http://localhost:5175`.

В Terraform несекретные значения задаются в существующем `service_environment`,
учётные данные — через Lockbox. Добавляйте их к имеющимся значениям, сохраняя
остальные настройки. Перед выкладкой проверьте effective environment контейнера:
сохранённые `live_service_environment` могут содержать прежние SMTP-настройки.
Один и тот же отправитель используется в новых и существующих письмах сервиса.

Контейнер YC использует конкретную версию Lockbox: после изменения пароля
создайте ревизию backend с новой ссылкой `version_id` для `EMAIL_HOST_PASSWORD`
и актуальными SMTP-параметрами. Остальные секреты и настройки сохраните.
`scripts/ci/snapshot-yc-runtime.py` переносит в следующий Terraform rollout
значения именно активной ревизии; простого добавления новой версии в Lockbox
недостаточно. Для проверки только настроек можно сохранить текущий образ
по digest. Код новых страниц и API восстановления выкладывается отдельно
обычным процессом релиза.

После настройки SMTP, из каталога `services/id` в том же окружении, что и backend,
можно отправить диагностическое письмо на свой адрес:

```sh
uv run --frozen python src/manage.py sendtestemail YOUR_TEST_RECIPIENT
```

Затем проверьте через интерфейс регистрацию, повторное подтверждение, сброс
пароля и письмо о завершении сброса на собственном тестовом аккаунте. Успешный
SMTP-ответ означает принятие письма сервером; попадание во входящие проверяется
в почтовом ящике получателя.

iCloud требует пароль приложения и двухфакторную защиту Apple Account. После
смены основного пароля Apple все пароли приложений отзываются: секрет SMTP нужно
обновить. Источники: [SMTP Apple](https://support.apple.com/en-us/102525),
[пароли приложений](https://support.apple.com/en-us/102654),
[собственный домен](https://support.apple.com/en-us/102540).

## Ошибки доставки

В разработке по умолчанию используется console backend: письмо выводится в
терминал, во внешний почтовый ящик оно не отправляется. Для проверки реальной
доставки явно включите SMTP backend.

Запросы сброса и повторного подтверждения ограничены по IP и хешу email.
Публичный ответ одинаков для существующих и неизвестных адресов, в том числе
при ошибке SMTP. Ошибки доставки отмечаются в серверном журнале без текста
ответа SMTP, паролей и ссылок. Получение ответа `ok` не гарантирует доставку.
Сбой уведомления о завершённом действии не откатывает смену пароля. Очередь
повторных попыток пока отсутствует; после восстановления SMTP пользователь
может запросить письмо заново.
