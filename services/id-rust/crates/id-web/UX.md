# UpdSpace ID: задачи и состояния интерфейса

UpdSpace ID — точка входа в сервисы UpdSpace. Главная страница объясняет пользу
аккаунта: один вход, выбор доступа для приложений и возможность его закрыть.
Названия протоколов, библиотек и внутренних компонентов не являются
пользовательской навигацией.

## Карта задач

| Намерение человека | Экран | Следующий понятный шаг |
| --- | --- | --- |
| Войти в свой аккаунт | `/login` | Ввод пароля или ключа; если настроено, подтверждение вторым способом |
| Продолжить в другом сервисе | `/login?next=…`, затем `/oauth/consent` при необходимости | Сначала вход в ID, затем отдельное решение о новых разрешениях |
| Проверить доступ | `/account` → устройства или приложения | Завершить конкретную сессию или отозвать доступ приложения |
| Получить свои данные | `/account?section=data` | Подтвердить запрос, дождаться письма после 24 часов, открыть приватную ссылку |
| Удалить аккаунт | `/account?section=delete` после включения API, jobs и расписания | Сначала запросить нужную копию, прочитать последствия, подтвердить пароль и MFA; доступ закрывается сразу, очистка продолжается |
| Проверить удаление | `/admin/` | Оператор вводит известный номер заявки и читает состояние |

## Правила выбора и текста

- Права приложения, которые не нужны для входа, изначально выключены.
- Отказ от передачи данных имеет ясную кнопку и не маскируется под ошибку.
- Сохранение выбора для будущих входов — отдельное, изначально выключенное решение.
- Вход в ID сам по себе не означает выдачу приложению новых прав. Если ранее
  сохранённый выбор допускает автоматическое продолжение, текст не обещает
  обязательный экран согласия.
- Статусы `pending`, `running`, `cooldown`, `ready`, `failed`, `cancelled`
  переводятся в человеческие действия и сроки. «Готово» нельзя показывать до
  готовности файла и наступления времени доставки.
- Для экспорта явны адрес доставки, время ожидания, срок ссылки, способ отмены
  и поведение после удаления аккаунта. Уже принятый запрос сохраняется в
  отдельном escrow до доставки или истечения срока; удаление аккаунта не
  должно отменять его молча.
- Переименование и удаление ключа доступа выполняются во встроенной карточке:
  видны точный ключ, последствия, явная отмена и результат. Системные
  `prompt`/`confirm` не заменяют пользовательский сценарий.
- Если подтверждение регистрации ключа потеряно после отправки, результат
  считается неизвестным: новый запрос не запускается до обновления списка, а
  экран не утверждает, что ключа нет или резервные коды были получены.
- Публичная ссылка на архив держит секрет в URL fragment только до загрузки
  страницы. Браузерный тест проверяет, что секрет уходит в тело POST без cookie,
  не попадает в URL запросов или Referer, а недействительная ссылка не скачивает файл.
- Пока отложенный экспорт не включён во всех API, web и jobs, новая немедленная
  выгрузка в production недоступна. Ранее созданные операции остаются доступны
  по действующим ссылкам.
- Операторская страница честно называется проверкой заявки. Она не изображает
  полноценную панель управления, пока другие операторские действия не имеют UI.

## Проверка перед выкладкой

Проверить клавиатурой и экранным диктором заголовки, подписи полей, ошибки,
порядок фокуса, отказ и подтверждение. Просмотреть 320, 375, 768 и 1440 px,
светлую и тёмную тему, масштаб текста 200%. Для экспорта прогнать состояния
без подтверждённой почты, ожидание, готово, ошибка, отмена, удаление аккаунта
после запроса. Для входа в дочерний сервис — первый вход, сохранённое согласие,
новые права, отказ, MFA и возврат после ошибки сети. Сверить каждый текст с
действительным состоянием API, а не только со снимком страницы.

Операторская админка и полная локализация не входят в пользовательский редизайн.
Сохранённый English означает предпочтение аккаунта, а не готовый перевод UI.
Браузерные проверки с синтетическим API и реальные Rust/YDB сценарии запускаются
отдельно; они не подтверждают доставку production-писем и очистку данных.

Удаление аккаунта нельзя предлагать как готовое действие в кабинете, пока
production API и отдельное расписание очистки не включены вместе с отложенным
экспортом. При наличии принятой заявки на копию удаление должно сначала
заблокировать вход, затем сохранить подготовленный архив и адрес доставки
отдельно от аккаунта. Письмо через 24 часа должно приходить и после удаления.


## Оболочка и визуальные правила

Постоянный порядок: Обзор → Профиль → Вход и защита → Устройства → Приложения →
Приватность и данные. Раздел скрывается только вместе с соответствующей серверной
возможностью. На телефоне тот же список раскрывается под шапкой. История входов
входит в Устройства; язык, часовой пояс и оформление — в Профиль.

Кобальтовый акцент, системная типографика, светлая/тёмная/системная тема. Основной
текст 16 px; целевые области действий от 44 px, видимый клавиатурный фокус,
уменьшение движения согласно системной настройке. Цветовые пары обычного текста
проходят порог 4.5:1. Компактные строки профиля показывают текущие значения и
раскрывают одну группу редактирования; ошибка не удаляет введённое.

Главная и прямой `/login` учитывают текущую сессию. На входе с `next` сохраняется
форма подтверждения личности: предложение текущего аккаунта не обходит reauth.
После запроса MFA почта/пароль скрыты, а действие «Вернуться к паролю» сбрасывает
только шаг MFA. Запрос входа, уже отправленный серверу, по-прежнему не отменяется.

Дополнительные данные и маркетинговое согласие в регистрации раскрываются по
действию, по умолчанию подписка выключена. Возрастной флаг и обязательное согласие
остаются в основном шаге; возраст, родительское согласие и подтверждение почты
проверяются существующим API.

Браузер/платформа устройства — приблизительная подпись из User-Agent; исходная
строка и IP доступны в раскрытии. Время отображается в часовом поясе устройства,
точный ISO момент сохраняется в datetime/title. Завершённые сеансы отделены от
действующих и не имеют повторного действия отзыва.

Резервные коды можно явно скопировать или скачать. Ошибка clipboard предлагает
ручное копирование. Эти действия не снимают предупреждение об уходе: только
«Я сохранил коды — продолжить» завершает шаг и перечитывает состояние сервера.

Внешние аккаунты в разделе защиты выводятся сразу из полученного SSR `/auth/me`,
включая просмотр без JavaScript. Повторного запроса профиля при загрузке нет;
callback query не доказывает привязку. Подключение показывается только при `login_enabled: true`
соответствующего провайдера и известном `oauth_providers`. Перед переходом ещё раз
проверяется текущий аккаунт. При смене аккаунта требуется повторный выбор действия.
Запрос привязки содержит только `{}`; владельца и свежесть входа проверяет сервер.
Режим `/login?reauth=provider-link` пропускает восстановление старой сессии, использует
существующие способы входа и возвращает в защиту без автоматической привязки.
Неопределённый begin требует проверки связей и подтверждённой отмены перед новым
действием. Отвязка и замена не предлагаются.

`scripts/check-web-provider-link-browser.cjs` проверяет эти состояния на настоящем
Topcoat с синтетическим API, включая CSRF, MFA, отключённые gates, подмену callback,
неверные внешние URL, ошибки сети и мобильную клавиатурную навигацию. Этот тест
не заменяет приёмку GitHub/Discord OAuth и Steam OpenID с реальными credentials.
